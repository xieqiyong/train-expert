# 资源存储结构说明

## 1. 说明

本文档描述当前 `expert-web` 实现下，各类资源的物理存储路径、文件类型、目录结构，以及数据库中常见路径字段的语义。

本文档只描述当前代码实现，不代表未来一定不变。

## 2. 当前配置根路径

当前 `application.yml` 中的关键路径配置如下：

- 训练输出根目录：`/var/dacheng/agent/output/`
- 规范 skill 路径：`/var/dacheng/agent/skills/root-skills-creator/`
- 共享存储根目录：`/var/dacheng/upload/static`

其中：

- 训练输出根目录用于训练阶段生成 skill 产物。
- 共享存储根目录用于上传原始包、技能包入库、静态资源包入库、专家发布包落盘。

## 3. 上传原始包

上传服务将应用原始包保存到共享存储根目录下的 `jars` 目录。

路径规则：

```text
/var/dacheng/upload/static/jars/{appName}/{timestamp}/
```

典型结构：

```text
/var/dacheng/upload/static/jars/webapp/1773976607797/
├── webapp_app_info.tar
└── app_info/
    ├── app.json
    └── jars/
        ├── app.jar
        ├── lib-a.jar
        └── lib-b.jar
```

说明：

- `appName` 从上传文件名解析得到，例如 `webapp_app_info.tar` 会解析出 `webapp`
- `timestamp` 为上传时间戳
- 原始包解压后必须存在 `app_info/`
- 当前支持的上传压缩类型：
  - `zip`
  - `tar`
  - `tar.gz`
  - `tgz`

## 4. 训练输入

训练任务内部记录的训练源，仍然是 `app_info` 目录路径。

示例：

```text
/var/dacheng/upload/static/jars/webapp/1773976607797/app_info
```

但提交给代理模型的可见输入路径，不是整个 `app_info`，而是：

```text
/var/dacheng/upload/static/jars/webapp/1773976607797/app_info/jars
```

也就是说：

- 系统内部训练源：`app_info`
- 模型可见输入：`app_info/jars`

## 5. 训练产物目录

当前训练产物目录已经改成“稳定 skill 根目录 + 版本目录”结构。

路径规则：

```text
{training.output-root}/{expertId}/{skillName}/
```

版本目录规则：

- 如果 `app.json` 中存在 `serviceVersion`，则直接使用该版本名
- 如果没有，则自动递增为 `v1`、`v2`、`v3`

典型结构：

```text
/var/dacheng/agent/output/5/webapp/
├── SKILL.md
├── v1/
│   └── static_package/
├── v2/
│   └── static_package/
└── v3/
    └── static_package/
```

说明：

- `skillName` 当前通常来自 `app_name`
- 根目录下的 `SKILL.md` 是 skill 主说明文件
- 每次训练只写当前版本目录
- 当前版本目录下必须存在 `static_package/`
- 当前实现要求代理把 jars 解压到版本目录的 `static_package/` 下

## 6. 技能包入库后的物理文件

训练产物校验通过后，会把 skill 根目录打成 zip 并写入共享存储。

路径规则：

```text
/var/dacheng/upload/static/skills/{skillId}/{packageName}
```

典型示例：

```text
/var/dacheng/upload/static/skills/8/webapp.zip
```

文件类型：

- 固定为 `zip`

说明：

- `packageName` 通常由 skill 目录名推导，例如 `webapp.zip`
- 数据库中的 `skill_package.package_path` 存的就是该 zip 的完整绝对路径

## 7. 静态资源包

静态资源包是另一套独立资源，不等同于训练版本目录里的 `static_package/`。

路径规则：

```text
/var/dacheng/upload/static/static_packages/{staticPackageId}/{packageName}
```

典型示例：

```text
/var/dacheng/upload/static/static_packages/12/task-executor.jar
```

文件类型：

- 当前常见是 `jar`
- 代码上并未强制只允许 `jar`

说明：

- 只有绑定到 `expert_static_package_binding` 的资源，才会在专家包外层 `static_packages/` 中出现
- 训练版本目录下的 `static_package/` 与这里的 `static_packages/` 不是一回事

## 8. 专家发布包

专家发布目录位于共享存储根目录下的 `experts` 目录。

根目录规则：

```text
/var/dacheng/upload/static/experts/{expertId}/
```

发布过程中使用两个目录：

- 暂存目录：`staging/{releaseTaskId}/`
- 当前目录：`current/`

典型结构：

```text
/var/dacheng/upload/static/experts/5/
├── current/
│   ├── expert-config.json
│   └── 5.zip
└── staging/
    └── release_xxx/
```

外层专家包文件名规则：

```text
{expertId}.zip
```

例如：

```text
/var/dacheng/upload/static/experts/5/current/5.zip
```

## 9. 专家包内部结构

当前专家包解压后的结构如下：

```text
5/
├── expert-config.json
├── skills/
│   └── webapp/
│       ├── SKILL.md
│       ├── v1/
│       │   └── static_package/
│       └── v2/
│           └── static_package/
└── static_packages/
    └── task-executor.jar
```

说明：

- `skills/` 下放的是技能包解压后的完整目录结构
- `static_packages/` 下放的是绑定到专家的静态资源包文件
- 专家包内一定包含 `expert-config.json`

## 10. 数据库中常见路径字段语义

### 10.1 `expert_training_task`

- `output_dir`
  - 当前训练版本目录的完整路径
  - 示例：`/var/dacheng/agent/output/5/webapp/v2`

- `manifest_path`
  - 当前不是文件路径
  - 存的是 JSON 数组字符串
  - 每个元素只包含 `name` 和 `path`
  - 其中 `path` 存的是 skill 根目录，不是版本目录

示例：

```json
[
  {
    "name": "webapp",
    "path": "/var/dacheng/agent/output/5/webapp"
  }
]
```

### 10.2 `skill_package`

- `package_path`
  - skill zip 的完整绝对路径
  - 示例：`/var/dacheng/upload/static/skills/8/webapp.zip`

### 10.3 `static_package`

- `package_path`
  - 静态资源包的完整绝对路径
  - 示例：`/var/dacheng/upload/static/static_packages/12/task-executor.jar`

### 10.4 `digital_expert`

- `shared_path`
  - 当前专家目录路径
  - 示例：`/var/dacheng/upload/static/experts/5/current`

- `config_json_path`
  - 当前专家配置文件路径
  - 示例：`/var/dacheng/upload/static/experts/5/current/expert-config.json`

- `zip_package_path`
  - 当前专家包路径
  - 示例：`/var/dacheng/upload/static/experts/5/current/5.zip`

## 11. 当前实现中的关键边界

当前要特别注意两层静态资源：

- 训练版本目录下的 `static_package/`
  - 属于 skill 内部版本资源
  - 是训练产物结构的一部分

- 专家包外层的 `static_packages/`
  - 来自 `static_package` 表以及专家静态资源绑定关系
  - 属于专家发布资源

这两层当前不是同一个概念，也不是同一个存储目录。

## 12. 一句话总结

当前资源流转关系可以概括为：

```text
上传原始包 -> 解压出 app_info -> 训练输出到 skill 根目录/版本目录 -> skill 打成 zip 入 skill_package -> 专家发布时组装 expert-config.json + skills + static_packages -> 生成 {expertId}.zip
```
