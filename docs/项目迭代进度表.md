# 项目迭代进度表

## 当前迭代项

### 训练完成后的处理流程

当前训练任务采用异步提交 + 定时轮询的方式处理，整体状态流转如下：

`PENDING -> RUNNING -> VERIFYING_ARTIFACTS -> IMPORTING_SKILLS -> RELEASING -> SUCCEEDED / FAILED / TIMEOUT`

### 1. 提交训练任务

1. 创建训练任务记录，写入 `expert_training_task`
2. 状态初始化为 `PENDING`
3. 记录输入源清单 `source_manifest_json`
4. 计算训练输出目录 `output_dir`
5. `manifest_path` 当前存储为 JSON 数组字符串，格式如下：

```json
[
  {
    "name": "task-executor",
    "path": "/root/skills/2/session_xxx/generated-skills/task-executor"
  }
]
```

### 2. 提交代理训练

1. 异步线程将任务置为 `RUNNING`
2. 专家状态改为 `TRAINING`
3. 清理并重建训练输出目录
4. 根据输入源文件名推导最终 skill 目录名
5. 组装提示词后调用代理服务 `chat`
6. 将代理返回的 `sessionId`、`requestId` 回写到训练任务
7. 将 `lastTrainingSessionId` 回写到专家表

说明：

1. 提示词中的规范 skill 路径仅用于告诉代理按哪个规范生成
2. 最终产物判断只看 `output_dir` 对应的 skill 目录，不再用规范 skill 路径参与产物校验

### 3. 轮询训练会话是否结束

1. 定时任务按 `poll-interval-ms` 轮询训练任务
2. 只轮询状态为 `RUNNING`、`VERIFYING_ARTIFACTS`、`RELEASING` 的任务
3. `RUNNING` 阶段通过 `sessionId` 调用代理的“会话是否结束”接口
4. 当前会话阶段超时时间为 30 分钟
5. 轮询次数 `pollCount` 仅用于日志节流，不再作为超时判断依据

当前配置：

1. `poll-interval-ms = 5000`
2. `session-timeout-ms = 1800000`

### 4. 会话结束后的缓冲处理

1. 当代理接口返回“会话已结束”后，任务状态切换为 `VERIFYING_ARTIFACTS`
2. 不立即做后续动作
3. 固定等待 2 分钟，作为产物落盘缓冲时间
4. 缓冲期间只打印日志，不导入技能、不触发发布

当前配置：

1. `artifact-grace-period-ms = 120000`

### 5. 校验训练产物

缓冲时间结束后，开始检查训练输出目录中的 skill 产物：

1. 先读取训练任务的 `output_dir`
2. 如果 `manifest_path` 中已有 JSON 数组，则按其中的 `path` 读取技能目录
3. 如果 `manifest_path` 为空，则按系统推导的 skill 目录名去 `output_dir` 下定位目录
4. 要求技能目录存在
5. 要求技能目录下存在 `SKILL.md`
6. 校验通过后，将 `name + path` 以 JSON 数组形式回写到 `manifest_path`

说明：

1. 当前默认一次训练只处理一个 skill
2. `manifest_path` 的 JSON 数组结构已兼容后续一训多 skill 的扩展
3. 如果 2 分钟缓冲结束后产物仍未就绪，当前实现会直接标记训练失败，不再继续无限等待

### 6. 导入技能包

产物校验通过后，进入 `IMPORTING_SKILLS` 阶段，处理逻辑如下：

1. 将 skill 目录压缩为 zip
2. 从 zip 中读取 `SKILL.md`
3. 解析 `name` 和 `description`
4. 向 `skill_package` 表插入一条技能包记录
5. 将 zip 文件写入共享存储目录
6. 回写 `package_path`

当前 zip 中 `SKILL.md` 的识别规则：

1. 优先读取 zip 根目录下的 `SKILL.md`
2. 如果根目录没有，再兜底读取任意子目录下的 `.../SKILL.md`

### 7. 替换专家技能绑定

skill 导入成功后：

1. 删除当前专家已有的 `expert_skill_binding`
2. 将本次训练导入的 skill 重新绑定到专家
3. 当前排序按导入顺序写入 `sort_no`

### 8. 触发专家发布

技能导入并绑定完成后：

1. 训练任务状态切换为 `RELEASING`
2. 调用发布服务创建发布任务
3. 将 `releaseTaskId` 回写到训练任务表
4. 后续轮询发布任务状态

当前发布阶段超时时间为 30 分钟：

1. `release-timeout-ms = 1800000`

### 9. 训练成功时的回写动作

当发布任务成功后，训练任务才真正结束，处理如下：

1. 训练任务状态改为 `SUCCEEDED`
2. `artifactVerified = 1`
3. 回写 `finishedAt`
4. 专家表回写 `lastTrainingTaskId`
5. 专家表回写 `lastTrainingSessionId`
6. 专家表的 `trainingVersion + 1`

### 10. 训练失败或超时处理

以下情况会导致任务失败：

1. 提交代理失败
2. 会话轮询超时
3. 缓冲结束后仍未找到有效 skill 产物
4. 技能包导入失败
5. 发布任务失败
6. 发布任务轮询超时

失败或超时后的处理：

1. 训练任务状态置为 `FAILED` 或 `TIMEOUT`
2. 回写 `failureReason`
3. 回写 `finishedAt`
4. 恢复专家训练前状态
5. 回写专家的 `lastTrainingTaskId`
6. 如果已有 `sessionId`，同时回写 `lastTrainingSessionId`

## 当前实现重点说明

### 规范 skill 与训练产物的边界

1. 规范 skill 路径只用于提示代理按既定规范生成 skill
2. 最终训练成功的判断只基于 `output_dir` 下的实际产物目录
3. 技能包解析时不再使用 `skills/root-skills-creator/SKILL.md` 这类规范路径判断最终产物

### 当前已落地的时间策略

1. 会话轮询最长 30 分钟
2. 会话结束后固定缓冲 2 分钟
3. 发布轮询最长 30 分钟
4. 轮询次数只用于打印进度日志

### 当前已落地的产物策略

1. 当前一次训练默认只生成一个 skill
2. skill 目录名默认按输入源文件名推导
3. 训练成功后会自动入库 `skill_package`
4. 训练成功后会替换专家当前绑定技能
5. 最终训练成功以“发布成功”为准

1. AI Agent 已提升为独立主实体，新增 `de_ai_agent`

1. 训练失败或超时后，保留训练任务记录，不删除训练源

4. 专家状态仍按原逻辑恢复，不影响成功链路

### 4. 当前待继续优化项

1. 训练任务排队目前仍主要依赖应用内线程池，尚未接入 Redis / MQ 级别的持久化排队
2. 训练会话结束判断仍采用定时轮询，后续需评估延迟队列或回调方案
3. 大训练源场景下，仍需继续优化任务调度、超时控制和存储清理策略
