# {项目名}问数语义

## 问数能力概述

**适用范围**：{项目名} {版本号}

**问数类型**：
- **指标查询**：查询特定指标的值、趋势、聚合
- **实体查询**：查询特定实体的属性、状态、关联
- **关联查询**：跨实体、跨环节的关联分析

**数据来源**：
- 实体定义来源于 `03-实体模型/{实体}.md`
- 字段来源追溯于 `02-领域认知/{环节}/{子环节}.md`
- 指标定义来源于各环节的【黄金指标】和【非黄金指标】
- **指标体系元数据**（训练时从 `/app/upload/data` 加载）：用于校验指标标识、黄金/非黄金分类及业务锚点；本文「业务语义 → 指标」映射必须与元数据及领域认知一致，禁止臆造指标名

**问数路径**：
```
用户问题
    ↓
04-场景能力/问数语义.md → 识别意图
    ↓
03-实体模型/{实体}.md → 定位实体和字段
    ↓
02-领域认知/{环节}/{子环节}.md → 追溯字段来源和业务逻辑
    ↓
构建查询 → 执行 → 返回结果
```

## 业务语义到指标的映射（指标体系元数据驱动）

> **目的**：将用户口语中的业务行为（接口调用、缓存操作、消息投递等）映射到可查询的**指标标识**，与排障/巡检共用同一套指标定义。

**生成规则**：
1. 以 `/app/upload/data` 中的条目为主：每条映射至少包含 **业务描述或锚点**（如 `POST /api/order/create`、Redis `EXPIRE`/淘汰、某 Topic 消费延迟）、**指标标识/名称**、**是否黄金**、**所属环节/子环节**（若有）、**推荐查询粒度**（瞬时/趋势）。
2. 与 `02-领域认知/` 对齐：映射中的环节、子环节、采集点描述须与对应 `整体逻辑.md` / `{子环节}.md` 一致；冲突以源码采集点为准更新说明，指标名以元数据为准。
3. **禁止**在本节写入元数据目录等内部路径；禁止列出元数据与源码均未出现的指标。

## 查询示例

### 示例1：简单实体查询

**用户问**："订单 ORD123456 的详情"

**解析过程**：
1. **实体识别**："订单" → {实体1}
2. **条件识别**："ORD123456" → {field1}（订单号）
3. **查询类型**：单实体详情查询
4. **字段来源追溯**：
   - 订单号来源于 `02-领域认知/{环节1}/{子环节A}.md`
5. **查询构建**：
   ```sql
   SELECT *
   FROM {entity1}
   WHERE {field1} = 'ORD123456'
   ```

### 示例2：实体统计查询

**用户问**："最近一小时的订单量"

**解析过程**：
1. **实体识别**："订单" → {实体1}
2. **时间识别**："最近一小时" → `time > now() - 1h`
3. **聚合识别**："量" → `COUNT(*)`
4. **时间字段来源**：`03-实体模型/{实体1}.md` 中的 {field5}（创建时间）
5. **字段来源追溯**：{field5} 来源于 `02-领域认知/{环节1}/{子环节A}.md`
6. **查询构建**：
   ```sql
   SELECT COUNT(*)
   FROM {entity1}
   WHERE {field5} > now() - 1h
   ```

### 示例3：关联实体查询

**用户问**："订单 ORD123456 的商品有哪些"

**解析过程**：
1. **主实体识别**："订单" → {实体1}
2. **关联实体识别**："商品" → {实体3}
3. **条件识别**："ORD123456" → {entity1}.{field1}
4. **关联关系**：查询 `03-实体模型/实体模型总览.md`
   - 发现 {实体1} 与 {实体3} 通过 {field_ref} 1:N 关联
5. **查询构建**：
   ```sql
   SELECT e3.*
   FROM {entity1} e1
   JOIN {entity3} e3 ON e1.{field_ref} = e3.id
   WHERE e1.{field1} = 'ORD123456'
   ```

### 示例4：趋势查询

**用户问**："展示过去一小时的订单创建趋势"

**解析过程**：
1. **实体识别**："订单" → {实体1}
2. **时间识别**："过去一小时" → `time > now() - 1h`
3. **分组识别**："趋势" → `GROUP BY time(1m)`
4. **聚合识别**：隐含统计 → `COUNT(*)`
5. **数据来源追溯**：订单创建来源于 `02-领域认知/{环节1}/{子环节A}.md`
6. **查询构建**：
   ```sql
   SELECT time(1m), COUNT(*)
   FROM {entity1}
   WHERE {field5} > now() - 1h
   GROUP BY time(1m)
   ```

### 示例5：TopN 查询

**用户问**："找出过去一天最慢的10个接口"

**解析过程**：
1. **实体识别**："接口" → {实体4}（接口调用实体）
2. **时间识别**："过去一天" → `time > now() - 1d`
3. **排序识别**："最慢" → 按 `{latency_field}` 降序
4. **限制识别**："Top 10" → `LIMIT 10`
5. **字段来源**：`03-实体模型/{实体4}.md` 中的延迟字段
6. **查询构建**：
   ```sql
   SELECT {interface_name}, AVG({latency_field}) as avg_latency
   FROM {entity4}
   WHERE {time_field} > now() - 1d
   GROUP BY {interface_name}
   ORDER BY avg_latency DESC
   LIMIT 10
   ```

## 问数执行流程

```
用户提问
    ↓
1. 意图识别（04-场景能力/问数语义.md）
   - 识别查询类型（实体查询/指标查询/趋势/TopN）
   - 识别时间范围
   - 识别聚合方式
    ↓
2. 实体匹配（03-实体模型/{实体}.md）
   - 匹配提到的实体名称
   - 获取实体字段定义
   - 确认字段可查询性
    ↓
3. 字段来源追溯（02-领域认知/{环节}/{子环节}.md）
   - 追溯字段产生的业务逻辑
   - 确认字段的业务含义
   - 验证字段的时效性
    ↓
4. 关联分析（03-实体模型/实体模型总览.md）
   - 识别是否需要关联查询
   - 确定关联实体和关联方式
    ↓
5. 查询构建
   - 组装 SELECT 字段
   - 组装 FROM 实体
   - 组装 WHERE 条件（时间 + 其他条件）
   - 组装 GROUP BY
   - 组装 ORDER BY + LIMIT
    ↓
6. 查询执行
   - 执行查询
    ↓
7. 结果格式化
   - 转换为自然语言描述
   - 必要时生成图表数据
   - 附加字段来源说明
    ↓
返回结果给用户
```

## 问数约束

1. **实体有效性**：查询的实体必须在 `03-实体模型/` 中定义
2. **字段有效性**：查询的字段必须在对应实体的字段清单中
3. **字段来源必填**：每个查询字段必须能追溯到 `02-领域认知/` 的具体子环节
4. **聚合合法性**：字符串字段不能进行 SUM/AVG 等数值聚合
5. **时间范围必填**：所有查询必须包含时间范围（默认最近10分钟）
6. **版本一致性**：使用当前选定版本的语义定义
7. **源码验证（按需）**：优先依据本文件与 `03-实体模型/`、`02-领域认知/`；**仅当**语义仍不明确、多义或与文档矛盾时，再读取 `static_package/` 验证字段映射
8. **禁止编造**：不得编造不存在的实体、字段或指标
9. **指标映射**：「业务语义 → 指标」须能在训练时使用的指标体系元数据（`/app/upload/data`）或 `02-领域认知/` 中找到依据；运行态答复用户时不得暴露内部路径，若未定义映射则明确告知「当前版本未收录该业务语义到指标的映射」

## 无法回答的情况

当遇到以下情况时，应明确告知用户无法回答：

1. **实体不存在**：用户查询的实体在 `03-实体模型/` 中未定义
2. **字段不存在**：用户查询的字段在实体字段清单中不存在
3. **关联不存在**：用户要求的实体关联在实体模型总览中未定义
4. **版本缺失**：当前版本缺少必要的实体定义文档

**回复模板**：
```
无法回答该问题，原因如下：
- {具体原因，如"订单实体在当前版本的实体模型中未定义"}

您可以选择：
1. 切换到其他版本尝试查询
2. 查询已定义的实体：{列出当前版本可用的实体列表}
```
