## 场景一：架构认知 / 原理解释

用于回答"这是什么"、"如何工作"、"为什么这样设计"等认知类问题。

### 执行流程

1. **选择版本号**；如果未指定则使用最新版本
2. **读取 01-项目总览/**：
   - `技术栈与架构.md` - 了解技术栈和部署架构
   - `目录结构.md` - 了解源码组织方式
   - `核心流程图.md` - 了解系统整体数据流
3. **读取 02-领域认知/整体架构.md**：
   - 了解项目包含哪些环节
   - 了解各环节的黄金指标定义
4. **按需深入 02-领域认知/{环节}/**：
   - `整体逻辑.md` - 了解环节内子环节划分和流程
   - `{子环节}.md` - 了解具体逻辑细节
5. **读取 03-实体模型/实体模型总览.md**：
   - 了解系统有哪些核心数据实体
   - 了解实体间的关联关系
   - 了解实体与环节的映射关系
6. **必须读取 static_package/ 源码验证**（硬性约束）：
   - 将文档认知与源码实现对比
   - 若不一致，以源码为准
7. **综合文档认知、源码事实与版本上下文**，给出完整、准确的解释

### 入口文档

- `{版本}/01-项目总览/技术栈与架构.md`
- `{版本}/02-领域认知/整体架构.md`
- `{版本}/03-实体模型/实体模型总览.md`
- `{版本}/static_package/`

## 场景二：智能问数

用于回答"查询某指标"、"统计某数据"、"对比某趋势"等数据查询类问题。

### 执行流程

1. **选择版本号**；如果未指定则使用最新版本
2. **读取 {版本}/04-场景能力/问数语义.md**：
   - 了解可查询的实体列表
   - 了解预定义的查询模板
3. **读取 {版本}/03-实体模型/{实体}.md**：
   - 获取实体的字段定义
   - 了解字段的来源环节（追溯数据血缘）
4. **追溯字段来源**：
   - 从实体模型追溯到 `02-领域认知/{环节}/{子环节}.md`
   - 确认字段的业务含义和产生逻辑
5. **必要时读取 static_package/ 验证字段映射**
6. 将用户问题转换为可执行查询，返回结果

### 问数路径示例

```
用户问："最近一小时的订单量"
    ↓
1. 识别实体："订单" → 03-实体模型/订单.md
2. 识别字段："量" → 计数，时间字段 → 创建时间
3. 追溯来源：订单创建时间来源于 02-领域认知/订单服务/订单创建.md
4. 构建查询：SELECT COUNT(*) FROM order WHERE create_time > now() - 1h
5. 返回结果
```

### 入口文档

- `{版本}/04-场景能力/问数语义.md`
- `{版本}/03-实体模型/实体模型总览.md`
- `{版本}/03-实体模型/{具体实体}.md`

## 场景三：故障排查（九步法则）

用于定位系统故障、分析异常根因。

### 执行流程

1. **选择版本号**；如果未指定则使用最新版本
2. **读取 {版本}/04-场景能力/故障排查思路.md**
3. **严格执行九步法则**（禁止跳跃、禁止提前下结论）：

#### 第一步：明确查询时间
- 如果用户已提供 queryStartTime、queryEndTime，则直接使用
- 如果没有，调用 `getCurrentTimeRangeMillis` 获取当前查询时间范围（推荐 600000ms）

#### 第二步：加载配置
- 调用 shuku skill 加载当前项目的配置文件（如果配置文件为空则代表没有采集对应的配置文件则忽略）

#### 第三步：全局扫描
- 加载 `02-领域认知/整体架构.md`，提取所有环节的黄金指标

#### 第四步：数据获取
- 调用 shuku skill 一次性查询上述所有环节的黄金指标
- 构建 MetricRequest（identifiers、entityHost/entityPort、时间范围）

#### 第五步：挑出有问题的环节
- 使用 queryAndDrillDown 工具分析黄金指标，找出有问题的指标
- **指标验证（必须严格执行）**：指标必须在 `[abnormalStartTime, abnormalEndTime]` 内有吻合的波动时间点才算异常
- 若某环节黄金指标异常，则标记该环节为有问题

#### 第六步：环节的详细分析
- 对有问题的环节，加载对应的 `02-领域认知/{环节}/整体逻辑.md`，提取非黄金指标
- 按需加载 `02-领域认知/{环节}/{子环节}.md` 获取逻辑细节
- **数据定位时参考 `03-实体模型/`**：
  - 通过实体找到异常数据的具体位置
  - 追溯字段来源，确认数据产生环节
- 查询非黄金指标并进行下钻
- **因果链条建立**：必须描述"因为指标 A 突变导致了指标 B 的异常"，严禁孤立看待指标
- **最终验证（必须严格执行）**：所有推导出的原因，其对应指标必须在时间窗内有吻合的波动
- 若文档不足以支撑结论，读取同版本 `static_package/` 进行源码级补充分析

#### 第七步：资源分析
- 根据组件的 host 和 port，调用 detectEntity 找到对应的资源层实体
- 调用资源层 skill 对 CPU、Memory、IO、Net 等进行分析

#### 第八步：结论推演
- 仅基于已识别的异常指标，推理 1～3 条因果链条（根因指标 → 中间指标 → 结果指标）
- **根因判定（硬约束）**：根因指标必须在时间窗内发生突变，突变需为数值级异常
- 若黄金指标在时间窗内均无突变：**直接输出 `未发现异常`，禁止假设根因**
- **因果校验（必须全部满足）**：机制合理、时间顺序正确、符合系统架构、无更合理替代解释
- **输出约束**：最终仅允许一个结论，禁止多根因、模糊或猜测性结论

#### 第九步：决策是否下钻到宿主机
- 如果最终根因是资源层的问题，继续下钻到宿主机分析
- 如果已找到明确的组件级根因，且与资源层无关，直接输出结论和优化建议

## 场景四：巡检

用于执行系统健康检查、生成巡检报告。

### 执行流程

1. **选择版本号**；如果未指定则使用最新版本
2. **读取 {版本}/04-场景能力/巡检清单.md**
3. **按清单逐项检查**：
   - 读取 `02-领域认知/整体架构.md` 获取各环节黄金指标
   - 读取 `03-实体模型/实体模型总览.md` 了解数据实体范围
   - 按清单定义的检查频率、预期值进行核查
4. **数据检查时参考 `03-实体模型/`**：
   - 确认检查的数据实体
   - 通过实体生命周期了解数据产生规律
5. **异常标记**：
   - 指标偏离预期值 → 标记异常
   - 关联 `02-领域认知/{环节}/{子环节}.md` 中的故障模式
6. **生成巡检报告**：
   - 正常项汇总
   - 异常项详情（现象、可能原因、建议措施）
7. **必要时转入排障流程**

### 入口文档

- `{版本}/04-场景能力/巡检清单.md`
- `{版本}/02-领域认知/整体架构.md`（黄金指标）
- `{版本}/03-实体模型/实体模型总览.md`（数据范围）

## 使用约束

### 认知类问题硬约束

- **禁止**仅依据认知文档（`01-项目总览/`、`02-领域认知/`、`03-实体模型/` 下的 `.md`）直接输出最终认知结论
- **必须**在选定版本目录下读取 `static_package/` 中的源码并完成深度分析后再作答
- 若认知文档与 `static_package/` 中源码行为不一致，**以源码分析结果为准**
- 若 `static_package/` 为空或缺失可读源码，须在回答中明确说明该限制，并仅基于文档给出带置信度说明的结论，不得假装已完成源码验证

### 排障类问题硬约束

- **禁止**在 skill 根目录放置全局共享的 `故障排查思路.md`
- 排障 SOP **仅允许**出现在各 `{版本目录}/04-场景能力/故障排查思路.md`
- 必须严格按九步法则执行，禁止跳跃、禁止提前下结论
- **必须使用实体模型进行数据定位**：通过 `03-实体模型/` 追溯字段来源，定位异常数据

### 问数类问题硬约束

- **必须**通过 `03-实体模型/` 确认实体字段定义
- **必须**追溯字段来源到 `02-领域认知/{环节}/{子环节}.md`
- 不得编造字段或指标，所有查询字段必须能在实体模型中找到

### 通用约束

- 根 `SKILL.md` 只负责版本选择、场景路由和约束声明
- 不要把详细排障 SOP、巡检清单、问数语义直接写在根 `SKILL.md` 中
- 若存在多个版本，必须体现"不同版本相互独立"的原则
- 文档内部禁止出现本地绝对路径和网络 URL
