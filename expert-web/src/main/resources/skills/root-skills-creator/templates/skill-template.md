# {项目名} Skill

## 版本选择

- 优先识别用户指定的版本号、tag、镜像版本或快照名称
- 如果用户未明确指定版本，则使用最新版本
- 所有后续认知查询、排障分析和源码探索，都必须在选定版本目录下进行

## 认知查询

认知类问题必须走完整流程，不能只读文档就作答。

1. 选择版本号；如果未指定则使用最新版本
2. 在对应版本目录中查找相关认知文档
3. 优先阅读 `整体架构.md`、相关环节目录下的 `整体逻辑.md` 和逻辑细节文档，形成初步理解
4. **必须**继续读取该版本 `static_package/` 中的源码进行深度分析与验证
5. 综合文档认知、源码事实与版本上下文，给出合理、完整的认知回答

## 故障排查

1. 选择版本号；如果未指定则使用最新版本
2. 在**选定版本目录**下读取 `故障排查思路.md`（与 `整体架构.md` 同级），严格按其中流程执行
3. 在同一版本目录中加载相关认知文档进行排查
4. 如果需要进一步分析代码，则读取该版本 `static_package/` 中的源码继续分析
5. 给出最终排查结论和建议

## 版本入口

- `{最新版本目录}/故障排查思路.md`
- `{最新版本目录}/整体架构.md`
- `{最新版本目录}/static_package/`
- `{其他版本目录}/...`（结构相同，每版本含独立的 `故障排查思路.md`）

## 使用约束

- 根 `SKILL.md` 只负责版本选择、认知查询入口、排障入口和版本入口导航
- 不要把详细排障 SOP 直接写在根 `SKILL.md` 中
- 若存在多个版本，必须体现“不同版本相互独立”的原则
- 文档内部禁止出现本地绝对路径和网络 URL

## 认知类问题硬约束

- **禁止**仅依据认知文档（`整体架构.md`、各环节目录下的 `.md`）直接输出最终认知结论
- **必须**在选定版本目录下读取 `static_package/` 中的源码并完成深度分析后再作答
- 若认知文档与 `static_package/` 中源码行为不一致，**以源码分析结果为准**
- 若 `static_package/` 为空或缺失可读源码，须在回答中明确说明该限制，并仅基于文档给出带置信度说明的结论，不得假装已完成源码验证
