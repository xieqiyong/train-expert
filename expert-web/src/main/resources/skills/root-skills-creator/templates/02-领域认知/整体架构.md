### 环节定义总览

> **环节识别约束**：环节列表必须基于 `static_package/` 的源码结构全面识别，禁止遗漏核心模块，但也禁止将基础设施/工具包列为环节。识别原则：
> - **哪些应该列为环节**：
>   - 按**业务包/模块语义**映射（如 APM、订单；生成时可在内部对照 `static_package/`，表内只写语义名，不写包全名与路径）

>   - 每个**独立技术组件**有独立入口和核心逻辑的，必须单独定义环节
> - **哪些禁止列为环节（纯基础设施/通用包）**：
>   - 通用工具包：`util`、`utils`、`common`、`helper`、`tools`
>   - 配置/常量/异常定义：`config`、`configuration`、`constants`、`constant`、`exception`、`exceptions`、`enums`
>   - 无业务入口的纯接口/抽象层：`abstracts`、`interfaces`（纯接口定义）
> - **禁止合并**：不能将 "APM + RUM + 告警" 合并为一个大环节，如果有独立的源码目录和 API 入口，必须分别定义
> - **双向校验**：本表列出的每个环节必须在同目录下存在 `{环节}/` 文件夹；同目录下的每个 `{环节}/` 文件夹必须在本表中有定义
