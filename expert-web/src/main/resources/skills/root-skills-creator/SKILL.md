# 故障定位 Skill 包生成器

## 使用说明

本技能用于分析项目代码并生成故障定位skill包。需要提供以下信息：

1. **项目名称**：要分析的项目名称
2. **项目代码路径**：要分析的项目源代码目录
3. **指标文件路径**：包含监控指标的Markdown文件（格式：## 指标名称\n描述）
4. **输出目录路径**：生成skill包的目标目录

---

## 执行流程

### 步骤1：验证输入
- 验证项目代码路径、指标文件是否存在且可读
- 验证输出目录是否可写

### 步骤2：读取指标文件
读取全部指标，每个指标格式为 `## 指标名称 + 描述`。

### 步骤3：分析项目代码结构

扫描目录结构，识别核心文件，抽象出以下概念层级：

```
整体架构
├── 环节（如：连接管理、内存管理）
│   ├── 子环节（如：客户端连接建立/断开）
│   └── 数据流程（串联子环节）
└── 整体数据流程（如：读流程、写流程、compact流程）
```

### 步骤4：生成 `整体架构.md`

内容要求：
- 每个环节的职责（1-2句话）
- 每个环节的黄金指标（1-5个）
- 核心数据流程（读写一致则合并）

### 步骤5：生成各环节文档

每个环节创建目录，结构如下：

```
{环节名}目录/
├── 整体逻辑.md
├── {子环节1}.md
├── {子环节2}.md
└── ...
```

**`整体逻辑.md` 内容要求：**
- 环节功能概述
- 子环节列表及职责
- 环节级数据流程（含指标和配置参数）
- 黄金指标（1-5个）与非黄金指标
- 常见故障模式（核心内容）

**`{子环节}.md` 内容要求：**
- 子环节功能
- 逻辑细节（含指标和配置参数，高层描述，无代码细节）
- 黄金指标（1-5个）与非黄金指标
- 常见故障模式（核心内容）

### 步骤6：生成 `SKILL.md`（主文件）

**严格按照以下模板生成，禁止增加多余章节：**

```markdown
---
name: {项目名}
description: 使用此技能进行{项目名}的故障定位
---
# {项目名} 故障定位技能

## 7步运行流程
1. **明确时间**: T_now = getCurrentTime, T_start = T_now - 600000, T_end = T_now
2. **加载配置**: 加载 {配置文件名}，获取 {关键配置项列表}
3. **全局扫描**: 通过监控指标全局扫描各环节健康状态，定位问题环节
4. **数据获取**: 获取问题环节的详细指标数据
5. **挑出有问题的环节**: 基于指标异常确定具体问题环节
6. **环节详细分析**: 对问题环节进行深入分析，递归分析子环节
7. **结论**: 给出故障原因和处置建议

## 一次性输出要求
获取数据后，在内部完成所有逻辑推理，严禁输出"准备进入下一步"等过渡语，必须一次性输出完整分析报告。

## 递归分析
如果某个环节有多个子环节，需要递归分析每个子环节，直至定位到具体问题。

## 配置文件加载
在第二步中加载以下配置：
{逐行列出：配置key: 说明}

## 可引用的指标和配置参数
{按环节分组，每组格式：}
### {环节名}
- {指标名1}
- {指标名2}
- {配置参数1}

## 排查原则
1. **优先处理**: 根据故障现象缩小排查范围
2. **SOP原则**: 所有排查必须以.md文档为标准作业程序
3. **知识查阅优先级**（按序执行，前一级有明确结论则不进入下一级）：
   - 第一级：查阅本skill的各环节.md文档、指标说明、架构说明
   - 第二级：查阅配置文件、应用说明、目录结构
   - 第三级：以上两级**均无明确结论或结论模糊**时，进入 `static_package/` 目录阅读采集的源码或原始信息，补充分析依据
4. **精准权衡**: Skill逻辑命中→引用文档原文给出建议；未命中→说明"已排查完私有知识库，未发现匹配项"后再补充通用知识
5. **禁止跳跃**: 在Skill路径未走完前不得直接给出通用结论

## 版本信息
### v1 - {当前日期}
- 初始版本
- 基于{项目名}源码生成
- 覆盖{环节列表}

## 关键文档入口
- [整体架构](v1/整体架构.md)
{逐行列出：- [{环节名}](v1/{环节名}目录/整体逻辑.md)}
```

### 步骤7：输出文件清单

```
{输出目录}/
├── SKILL.md                          ← 故障定位skill主文件
└── v1/
    ├──static_package/             ← 解压后的源码包路径
    ├── 整体架构.md
    ├── {环节1}目录/
    │   ├── 整体逻辑.md
    │   ├── {子环节1}.md
    │   └── {子环节2}.md
    ├── {环节2}目录/
    │   └── ...
    └── ...
```

## 内容约束（必须遵守）

### ✅ 应该包含
- 环节/子环节功能的高层描述
- 数据流程（概念性，含指标和配置参数名）
- 黄金指标与非黄金指标的分类
- 常见故障模式：**什么情况 → 哪些指标异常 → 可能原因**
- 时间展示：调用 `formatTime(时间戳)` 工具，已出现过的时间戳直接复用，禁止重复调用

### ❌ 禁止包含
- 具体函数名、文件名、代码行数
- 具体数据结构名、字段名、参数名
- 内存分配、缓冲区管理等实现细节
- 具体系统调用（epoll、kqueue等）
- 协议格式、消息格式等实现细节
- 代码流转说明
- 监控指标的经验阈值
- 本地路径（`/Users/xxx`）或网络URL

### 版本追加规则
- 同一项目再次生成时，在 `SKILL.md` 末尾**追加**新版本信息，不得覆盖历史版本记录

## 设计说明

故障定位skill的目的是帮助LLM**通过指标和运行逻辑进行诊断**，而非理解代码实现。

因此文档聚焦于：
- **故障模式**：什么情况会出现什么问题
- **指标特征**：哪些指标能反映哪类问题
- **运行逻辑**：高层数据流转描述
- **配置参数**：影响运行逻辑的关键配置
