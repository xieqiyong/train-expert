# Skill 包生成器

## 提供的信息

使用本技能时，只需要用户提供以下信息：

1. **项目名称**：要分析的项目名称
2. **项目代码路径**：要分析的项目源代码目录
3. **指标文件路径**：包含监控指标的 Markdown 文件（格式：## 指标名称\n描述）
4. **输出目录路径**：生成 skill 包的目标目录

## 生成目标

## 生成要求

### 1. 版本目录

- 每个版本目录代表一个独立快照，目录名可以是 tag、镜像版本、发布日期或其他可稳定标识版本的名称
- 如果能识别多个版本，则分别生成多个版本目录
- 如果没有明确版本信息，则至少生成一个默认版本目录（如 `latest/` 或 `v1.0.0/`），并在根 `SKILL.md` 中将其视为最新版本
- 不同版本目录下的所有内容相互独立，禁止混写

### 2. 01-项目总览/（全局认知层）

- **位置**：`{版本目录}/01-项目总览/`
- **内容**：
  - `技术栈与架构.md`：技术栈、核心依赖、部署架构
  - `目录结构.md`：源码目录结构、关键文件说明
  - `核心流程图.md`：系统整体数据流、关键业务流程
- **用途**：为所有场景提供项目级上下文
- **模板来源**：`templates/01-项目总览/`

### 3. 02-领域认知/（核心认知层）

采用**三层强制关联结构**：

#### L2: 整体架构.md（项目级）
- **位置**：`{版本目录}/02-领域认知/整体架构.md`
- **模板**：`templates/02-领域认知/整体架构.md`
- **必须包含**：
  - **架构概述**：架构类型、特点、版本信息
  - **技术栈详单**：框架、中间件、存储、运维组件（含版本和部署方式）
  - **部署架构**：拓扑图、环境配置、网络架构
  - **目录结构**：源码组织、关键文件说明
  - **系统依赖**：外部依赖（超时、熔断、故障影响）、被依赖关系
  - **环节与黄金指标**：所有环节列表、黄金指标（含采集点、告警级别）、容量规划、故障影响
  - **核心数据流程**：流程图、步骤详单、数据转换、状态机
  - **故障模式总览**：各环节故障模式索引
- **关联约束**：每个在此列出的环节，必须在同目录下有对应的 `{环节}/` 文件夹

#### L3: {环节}/整体逻辑.md（环节级）
- **位置**：`{版本目录}/02-领域认知/{环节}/整体逻辑.md`
- **模板**：`templates/02-领域认知/整体逻辑.md`
- **必须包含**：
  - **环节基本信息**：名称、职责、输入输出、架构位置
  - **上下游关系**：依赖图谱、调用方式、SLA要求
  - **子环节与黄金指标**：子环节列表、黄金指标（含采集点、告警级别）、性能指标（RT/吞吐量/错误率）
  - **核心数据流程**：流程图、步骤详单、数据转换、状态机、配置参数
  - **非黄金指标**：辅助监控指标、业务指标、资源指标
  - **常见故障模式**：故障概述、症状、指标特征、可能原因（含概率）、排查建议（快速+深度）、解决方案（临时+长期）
  - **限流与降级**：限流策略、降级策略
  - **下游关联**：依赖详情、被依赖关系
  - **配置参数汇总**：核心配置、性能配置、超时配置
- **关联约束**：每个在此列出的子环节，必须在同目录下有对应的 `{子环节}.md` 文件

#### L4: {环节}/{子环节}.md（细节级）
- **位置**：`{版本目录}/02-领域认知/{环节}/{子环节}.md`
- **模板**：`templates/02-领域认知/子环节.md`
- **必须包含**：
  - **子环节基本信息**：名称、职责、代码位置
  - **类结构**：核心类清单、类关系图、核心方法列表
  - **逻辑细节**：业务场景、处理流程、详细步骤（含方法签名、行号）、数据模型、异常场景
  - **调用链分析**：同步调用链、异步调用链、调用详情（超时、重试、熔断）
  - **黄金指标**：核心监控指标（含采集点、告警级别）、指标关联关系
  - **非黄金指标**：详细分析指标、业务指标
  - **常见故障模式**：故障概述（等级/类型/MTTR）、症状、指标特征（时间轴）、可能原因（概率排序）、排查步骤（含诊断命令）、解决方案、优化建议
  - **上游依赖**：依赖服务详情（含故障场景）
  - **下游影响**：影响服务详情
  - **配置参数汇总**：核心/性能/限流/超时配置
  - **性能特征**：性能基线、资源消耗、性能瓶颈
- **下限约束**：若某环节在 `整体逻辑.md` 中暂未拆分子环节，则该环节目录下仍须至少生成 **2 份** 由 `子环节.md` 模板展开的细节文档，分别覆盖该环节下两条不同的关键数据流程或关键逻辑面

### 4. 03-实体模型/（数据模型层）

**设计目的**：
- 按**数据实体**横向组织，建立跨环节的数据视图
- 明确每个实体的字段来源于哪些领域认知环节
- 为问数、巡检提供统一的数据入口

**与 02-领域认知 的关系**：
- **02-领域认知**：按环节纵向组织（流程视角）
- **03-实体模型**：按实体横向组织（数据视角）
- 两者通过【字段来源】建立映射

#### 03-实体模型/实体模型总览.md
- **位置**：`{版本目录}/03-实体模型/实体模型总览.md`
- **模板**：`templates/03-实体模型/实体模型总览.md`
- **必须包含**：
  - 所有实体的列表和职责说明
  - 实体间的关联关系图
  - 每个实体的核心字段概览
  - 实体到环节/子环节的映射索引

#### 03-实体模型/{实体}.md
- **位置**：`{版本目录}/03-实体模型/{实体}.md`
- **模板**：`templates/03-实体模型/实体.md`
- **必须包含**：
  - 实体定义和业务含义
  - 字段清单（含字段来源：哪个环节/子环节产生）
  - 实体的生命周期（创建、更新、销毁涉及的环节）
  - 实体的查询方式（主键、索引、关联查询）
  - 实体相关的指标（可查询的指标列表）

**字段来源标注示例**：
| 字段名 | 类型 | 来源环节 | 来源子环节 | 产生时机 | 说明 |
|-------|------|---------|-----------|---------|------|
| order_id | String | 订单服务 | 订单创建 | 创建时 | 主键 |
| status | Enum | 订单服务 | 订单状态机 | 状态变更时 | 状态字段 |

### 5. 04-场景能力/（场景应用层）

场景文档**派生自** 02-领域认知 和 03-实体模型，不重复描述原理，只补充场景化信息：

#### 故障排查.md（按版本，不共享）
- **位置**：必须放在 `{版本目录}/04-场景能力/故障排查.md`
- **模板**：`templates/04-场景能力/故障排查.md`
- **特点**：
  - 严格遵循**九步法则**
  - 引用 `02-领域认知/` 中的架构知识
  - 引用 `03-实体模型/` 中的实体定义定位数据
  - 每个版本独立一份，禁止在 skill 根目录放置全局共享版本

#### 巡检清单.md
- **位置**：`{版本目录}/04-场景能力/巡检清单.md`
- **模板**：`templates/04-场景能力/巡检清单.md`
- **特点**：
  - 提取 `02-领域认知/整体架构.md` 中的黄金指标作为检查项
  - 引用 `03-实体模型/` 中的实体定义数据检查范围
  - 定义检查频率、预期值、异常判定标准

#### 问数语义.md
- **位置**：`{版本目录}/04-场景能力/问数语义.md`
- **模板**：`templates/04-场景能力/问数语义.md`
- **特点**：
  - 基于 `03-实体模型/` 中的实体定义构建可查询对象
  - 定义自然语言到实体/字段的映射
  - 定义查询模板、聚合方式

### 6. 05-自我进化/（经验知识库层）

**设计目的**：
- 记录 skill 在实际使用过程中积累的经验教训和成功路径
- 避免重复犯同样的错误，加速后续类似问题的处理
- 形成持续改进的闭环

**与 02/03/04 的关系**：
- **02-领域认知**：描述"应该是什么样"（设计态）
- **05-自我进化**：记录"实际发生了什么"（运行态）
- 两者通过【场景/环节/指标】建立关联

#### 05-自我进化/INDEX.md
- **位置**：`{版本目录}/05-自我进化/INDEX.md`
- **模板**：`templates/05-自我进化/INDEX.md`
- **必须包含**：
  - 经验教训索引（按环节/指标/场景分类）
  - 成功路径索引（按问题类型分类）
  - 常见陷阱速查表
  - 读取策略说明（何时读什么）

#### 05-自我进化/经验教训/{案例}.md
- **位置**：`{版本目录}/05-自我进化/经验教训/{案例}.md`
- **模板**：`templates/05-自我进化/经验教训.md`
- **必须包含**：
  - 问题现象（用户原始问题）
  - 初始判断（错误思路）
  - 实际根因（真相）
  - 纠正过程（如何发现修正）
  - 经验提炼（可复用的判断规则）
  - 关联文档（相关环节/实体）

#### 05-自我进化/成功路径/{场景}.md
- **位置**：`{版本目录}/05-自我进化/成功路径/{场景}.md`
- **模板**：`templates/05-自我进化/成功路径.md`
- **必须包含**：
  - 触发条件（关键词/指标特征）
  - 最优路径（步骤序列）
  - 效率分析（为什么这样最快）
  - 验证结果（成功案例）

#### 05-自我进化/常见陷阱/{陷阱}.md
- **位置**：`{版本目录}/05-自我进化/常见陷阱/{陷阱}.md`
- **模板**：`templates/05-自我进化/常见陷阱.md`
- **必须包含**：
  - 陷阱描述（什么情况下容易犯错）
  - 典型症状（如何识别）
  - 规避方法（预防措施）
  - 自查清单（执行前检查）

### 7. static_package/

- **位置**：`{版本目录}/static_package/`
- **用途**：
  - 存放对应版本的源码快照、反编译结果、静态资源
  - **认知类问题**：必须读取该目录中的源码做深度分析与验证
  - **实体模型验证**：验证实体字段在源码中的实际定义
  - **排障**：按当前选定版本的认知文档执行；需要代码佐证时，读取同版本 `static_package/` 继续分析

## 根 SKILL.md 生成规则

根 `SKILL.md` 按 `SKILL-template.md` 生成，必须包含：

### 1. 版本选择
- 优先识别用户指定的版本号
- 未指定则使用最新版本
- 所有后续操作必须在选定版本下进行

### 2. 四场景路由

```yaml
## 场景一：架构认知 / 原理解释（增强版）
1. 选择版本
2. 读取 01-项目总览/ 了解全局
3. 【经验检查点】读取 05-自我进化/INDEX.md → 查找是否有架构认知相关的经验教训
   - 如果存在 → 阅读教训，避免同样的误解
4. 读取 02-领域认知/整体架构.md 了解环节
5. 按需读取 02-领域认知/{环节}/ 了解细节
6. 读取 03-实体模型/实体模型总览.md 了解数据实体
7. 必须读取 static_package/ 源码验证
8. 【经验检查点】对比 05-自我进化/成功路径/ 中是否有类似解释场景
   - 如果存在优化路径 → 采用更有效的解释方式
9. 综合文档与源码给出解释

## 场景二：智能问数（增强版）
1. 选择版本
2. 【经验检查点】读取 05-自我进化/INDEX.md → 查找是否有类似问数场景的经验
   - 如果存在成功案例 → 采用验证过的查询路径
3. 读取 04-场景能力/问数语义.md 了解查询能力
4. 读取 03-实体模型/{实体}.md 获取实体字段定义
5. 追溯字段来源：从实体模型追溯到 02-领域认知/{环节}/{子环节}.md
6. 【经验检查点】检查 05-自我进化/常见陷阱/ 中是否有该实体的查询陷阱
   - 如果存在 → 按照陷阱规避方案处理
7. 必要时读取 static_package/ 验证字段映射
8. 将用户问题转换为查询并返回结果

## 场景三：故障排查（九步法则 + 经验增强）
1. 选择版本
2. 读取 04-场景能力/故障排查.md
3. 【经验检查点】读取 05-自我进化/INDEX.md → 索引经验教训和陷阱
4. 严格执行九步法则：
   - 步骤1-2：明确时间、加载配置
   - 步骤3-5：全局扫描（02-领域认知/整体架构.md 黄金指标）→ 挑出有问题环节
```

   - `03-实体模型/` 目录下是否存在 `实体模型总览.md` 和至少 2 个实体详情文件
6. **禁止项**：**禁止**在 skill 根目录放置全局共享的 `故障排查.md`
